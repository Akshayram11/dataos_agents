# Data Product Builder Skills routing

For a request to design, build, scaffold, or fix a Vulcan/DataOS data product, use the official `dataproduct-builder-skills` journey instead of recreating it from model knowledge.

Current published package verified by the Agent Builder: `dataproduct-builder-skills` 2.1.0. In generated project instructions, prefer the updateable command:

```bash
npx dataproduct-builder-skills@latest
```

The installer asks which host to scaffold for: Cursor, Claude Code, Codex, VS Code/Copilot, or all. For an agent generated by this application, select Codex unless the approved PRD names another host. It installs:

- `design-data-product`: takes an idea through structured discovery to a validated `data-product-plan.md`; requires the Data Product MCP.
- `build-data-product`: turns the validated plan into a Vulcan project, plans/evaluates, enriches metadata, adds quality checks, and deploys through dev/prod stages.
- `fix-data-product`: reads an existing `vulcan review` report and fixes approved blocker/high findings plus required AI-readiness gaps.
- `dpbs-docs/`: DataOS philosophy, Vulcan references, engine guidance, examples, and the packaged Vulcan wheel.

Engine selection is a CLI argument, not part of the interactive host prompt. Supported package engines are `athena`, `databricks`, `fabric`, `mssql`, `postgres`, `redshift`, `snowflake`, `spark`, and `trino`; omitting the engine installs examples for all. Ask for or infer an engine only from verified source/depot context, and record the choice in the PRD.

Important boundaries:

- Node.js 16+ is required to run the installer.
- Vulcan requires Python 3.10 or 3.11; the build skill creates a dedicated virtual environment.
- Do not treat Arguss/Vulcan consumption tools as build tools.
- `vulcan review` is experimental and opt-in. Never run it automatically. `fix-data-product` requires a report the user has already generated in `.vulcan/reviews/`.
- Do not execute `npx`, `pip`, or generated build commands during discovery or PRD generation. Put the exact install/build steps into the generated project. Execution starts only after the applicable approval gate.
- Re-check the package version and current DataOS docs when generating a project; `@latest` is intentionally updateable.
